# 后端工程化每日训练 Day 70：Linux inode 耗尽排障复盘

## 一、今天学习什么

主题：Linux inode 耗尽。

核心问题：

为什么 Linux 服务器出现：

```text
No space left on device
```

但是：

```bash
df -h
```

查看发现磁盘只用了 60%。

原因：Linux 文件系统不仅管理磁盘容量，还管理 inode 资源。

---

## 二、核心原理

Linux 文件系统主要有两类资源：

### 1. 数据块空间

负责存储文件真正的数据。

查看：

```bash
df -h
```

关注：

```text
Use%
```

表示磁盘容量使用率。

---

### 2. inode

负责保存文件元数据，例如：

- 文件权限
- 文件类型
- 文件大小
- 创建时间
- 数据块位置

查看：

```bash
df -i
```

关注：

```text
IUse%
```

---

## 三、为什么还有空间却无法创建文件？

创建文件不仅需要数据空间，还需要 inode。

流程：

```text
创建文件
    ↓
申请 inode
    ↓
记录文件元信息
    ↓
分配数据块
    ↓
写入内容
```

如果：

```text
df -h
正常
```

但是：

```text
df -i
100%
```

说明：

```text
数据空间还有
但是没有 inode 可以分配
```

因此无法创建新文件。

---

## 四、大文件和大量小文件的区别

### 场景 A：一个 50GB 文件

特点：

```text
文件数量少
inode消耗少
```

主要消耗：

```text
磁盘容量
```

---

### 场景 B：500 万个 1KB 文件

特点：

```text
文件数量巨大
```

每个文件都需要 inode。

可能出现：

```text
df -h 正常

df -i 满

无法创建新文件
```

结论：

> inode 耗尽通常来自大量小文件，而不是大文件。

---

## 五、真实故障场景

现象：

```text
Java 服务上传失败
```

日志：

```text
No space left on device
```

第一步：

查看容量：

```bash
df -h
```

发现：

```text
Use=55%
```

继续检查 inode：

```bash
df -i
```

发现：

```text
IUse=100%
```

定位：

```text
inode耗尽
```

继续查找：

```text
哪个目录产生大量文件
```

例如：

```text
/tmp/app-cache
```

发现：

```text
80万个临时文件
```

继续分析：

```text
谁创建？
为什么没有删除？
```

最终发现：

```text
Java异常路径没有执行临时文件清理逻辑
```

完整链路：

```text
生成临时文件
 ↓
处理失败
 ↓
没有删除
 ↓
文件不断累积
 ↓
inode持续下降
 ↓
无法创建新文件
 ↓
服务异常
```

---

## 六、排障方法

遇到：

```text
No space left on device
```

不要直接认为磁盘容量满。

排查：

```text
现象
 ↓
假设：容量不足 / inode不足
 ↓
证据：df -h、df -i
 ↓
确定异常文件系统
 ↓
定位大量文件目录
 ↓
分析文件来源
 ↓
找到创建者和代码逻辑
 ↓
修复根因
```

---

## 七、为什么不能直接全盘扫描？

不要直接：

```bash
find /
```

原因：

线上服务器可能存在：

- 数百万文件
- 大量目录
- 正在运行业务

全盘扫描可能：

- 消耗大量时间
- 增加 IO 压力
- 影响业务

正确方式：

```text
先确定异常文件系统
 ↓
逐层缩小目录范围
 ↓
定位文件产生位置
```

---

## 八、删除文件是否等于修复？

不是。

删除文件属于：

```text
故障恢复
```

不是：

```text
根因修复
```

还需要确认：

- 文件是否正在使用
- 是否属于业务数据
- 谁创建文件
- 为什么没有清理

长期修复：

- 修改代码清理逻辑
- finally 保证资源释放
- 增加临时文件生命周期管理
- 增加 inode 监控

---

## 九、监控设计

磁盘监控不能只看容量。

需要同时关注：

### 容量

```text
df -h
```

例如：

```text
磁盘使用率 > 85%
```

告警。

---

### inode

```text
df -i
```

例如：

```text
inode使用率 > 90%
```

提前告警。

---

## 十、今日总结

Linux 文件系统存在两种“满”：

```text
1. 容量满

df -h

2. inode满

df -i
```

遇到：

```text
No space left on device
```

排查思路：

```text
容量？
inode？
文件数量？
哪个程序创建？
为什么没有清理？
```

inode 是 Linux 服务器资源管理中的重要指标，和 FD 耗尽一样，都属于资源耗尽类故障。
